WORKFLOW EXAMPLES
═══════════════════════════════════════════════════════════════════════════════

Example 1: Individual Article (Auto-Published)
┌─────────────────────────────────────────────────────────────────────────────┐
│ POST /articles {                                                            │
│   title: "How to Learn Improv",                                            │
│   content: "...",                                                           │
│   authorType: "individual",                                                │
│   authorId: "user_123"                                                     │
│ }                                                                           │
│ → Response: status="published" (immediately)                               │
│ → Content is live and visible                                              │
└─────────────────────────────────────────────────────────────────────────────┘

Example 2: Organization Article (Requires Approval)
┌─────────────────────────────────────────────────────────────────────────────┐
│ POST /articles {                                                            │
│   title: "Summer Programs",                                                │
│   content: "...",                                                           │
│   authorType: "organization",                                              │
│   authorId: "org_123",                                                     │
│   organizationId: "org_123"                                                │
│ }                                                                           │
│ → Response: status="pending_approval"                                      │
│ → approvalChain: [admin_001, admin_002]                                    │
│                                                                             │
│ PATCH /articles/{id}/approve (as admin_001)                               │
│ → Response: approvalChain: [admin_002], status still "pending_approval"   │
│                                                                             │
│ PATCH /articles/{id}/approve (as admin_002)                               │
│ → Response: approvalChain: [], status="published"                          │
│ → Content is live                                                          │
└─────────────────────────────────────────────────────────────────────────────┘

Example 3: Rejection and Edit
┌─────────────────────────────────────────────────────────────────────────────┐
│ PATCH /articles/{id}/reject {                                              │
│   feedback: "Please update the dates"                                      │
│ }                                                                           │
│ → Response: status="rejected", rejectionFeedback stored                    │
│                                                                             │
│ PUT /articles/{id} {                                                       │
│   content: "Updated content with correct dates..."                         │
│ }                                                                           │
│ → Response: status still "rejected" (until resubmitted)                    │
│ → Creator can resubmit for approval again                                  │
└─────────────────────────────────────────────────────────────────────────────┘

KEY IMPLEMENTATION DETAILS
═══════════════════════════════════════════════════════════════════════════════

Request Handling:
  • All endpoints validate session (401 if missing)
  • Parse request body as JSON
  • Validate required fields (400 if missing)
  • Check user permissions (403 if insufficient)
  • Query database with Prisma
  • Return typed response objects

Approval Chain Logic:
  1. When content created with org/community/event authorType:
     → Populate approvalChain with relevant admins/curators
     → Set status to "pending_approval"
  
  2. When approver calls approve endpoint:
     → Remove approver from approvalChain
     → If chain empty → auto-publish, set status="published"
     → Otherwise keep status="pending_approval"
  
  3. When approver calls reject:
     → Set status="rejected"
     → Store feedback in tags field
     → Clear approvalChain
  
  4. When creator edits rejected content:
     → Allow PUT updates
     → Keep status as "rejected" until resubmitted

Visibility Rules:
  • public: All users see it
  • organization: Only org members see it
  • community: Only community members see it
  • event: Only event participants see it
  • private: Only creator/approvers see it
